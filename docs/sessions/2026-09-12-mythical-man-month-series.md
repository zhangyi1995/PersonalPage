# 会话记录：《人月神话》读书笔记系列（2026-09-12）

- 方法：`grilling` 技能，一次只问一个问题，每问都附推荐答案
- 参与者：站点所有者（决策方）与 Codex（提问、查证、落地）
- 状态：十项决定已确认，骨架已按结论落地

## 起因

用户打算写《人月神话》的读书笔记并做成一个系列，先要解决"放在主页的什么位置"，并要求先用 grilling 盘问一遍再动手。

## 十轮问答

1. **阅读形态与粒度** → 逐章推进为主，允许插入跨章主题篇。
2. **放在内容树哪里** → 留在 `content/blog/`，靠 series 串联，不另开栏目。
3. **文章形状** → 平铺在 `content/blog/`，文件名带系列前缀：`mythical-man-month-NN-<英文 slug>.md`。
4. **权重编号** → 从 10 起、步长 10，与文件编号对齐，为插篇预留空位。
5. **首页位置与文案** → 放进 `featured` 分区（不是 `columns`）；标题「我读《人月神话》」，描述「逐章笔记：为什么加人不能加快进度。」。
6. **英文首页** → 有意不加卡片；主题会强制补 `/en/` 前缀，指向中文系列页必然是死链。
7. **覆盖范围** → 19 章 + 尾声全覆盖，一条阅读路径，中途不拆成两个系列。
8. **首发节奏** → 引言 + 前两篇一起发；只有一篇时横幅不显示，两篇齐发整条链路才活。
9. **引言页是否列全书章目** → 不逐章列。只写读法与上下两部结构：静态路线图会变成负债，已发布目录交给系列页自动列表。
10. **本轮交付范围** → 结构骨架 + 前两篇写作骨架（front matter、小节锚点、每节一句提示），正文由用户填写。

## 决定摘要

- 系列标识符：`mythical-man-month`（ASCII）；显示名走 `content/series/mythical-man-month/_index.md` 的 `title`
- URL：`/blog/mythical-man-month-NN-<slug>/`，系列页 `/series/mythical-man-month/`
- 分类法：`categories: [读书笔记]`（领域）+ `tags: [人月神话]`（条目）
- 排序：`series_weight` 10/20/30…，与文件名前缀 `01/02/03` 一一对应
- 首页：中文首页 `featured` 加一张指向系列页的卡片；英文首页不动（有意不对称）
- 语言：本系列中文单语

## 遗留

- 各章中文章名待用户按手头版本校对；第 1、2 章暂用通行译名《焦油坑》《人月神话》。
- 英文版是否补齐未定；补的时候成对加 `_index.en.md` 与 `.en.md`。
- 正文写作属于用户本人，Agent 只维护结构与约定。
